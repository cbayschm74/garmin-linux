## Official API decision

Garmin says its [Connect Developer Program FAQ](https://developer.garmin.com/gc-developer-program/program-faq/) is **business-only**. It requires application and approval, uses OAuth 2.0, and is distinct from Connect IQ. Its [overview](https://developer.garmin.com/gc-developer-program/) describes cloud-to-cloud integrations: Activity API receives data from Connect; Courses API publishes courses to Connect. The [Activity API](https://developer.garmin.com/gc-developer-program/activity-api/) requires the user to sync the device with Connect before an approved partner can receive it. The [Courses API](https://developer.garmin.com/gc-developer-program/courses-api/) requires approval and then lets a partner publish courses for later device sync. There is no approval or API credential for this personal project, so automatic Connect sync is **blocked** on the official program path.

The local app should offer verified backups, activity FIT export for manual web upload, and direct course transfer. It can guide users through Connect's web and phone flows without handling their Garmin credentials. Browser import/export and phone Send to Device should be called documented paths until actually tried with this account.

## Optional automatic Connect connector: decision required later

If the user later wants automatic account sync despite the official program limit, assess a separate, opt-in unofficial connector before writing it. It would need explicit authorization to handle a Garmin login/session; secrets must stay outside Git and logs, session storage must be restricted, and logout/revocation must be possible. Garmin's private web flows may change or challenge sign-ins, so maintenance and breakage are likely. Define exactly which activity/course directions are requested, check account terms and the chosen library's behavior at that time, and test with a limited account action. This connector must remain optional; local backup and course transfer already work without it. No connector or credential handling is implemented now.

## Follow-up verification

1. When the user identifies an activity missing from Connect, upload its verified prepared FIT through Connect web and confirm the activity appears there. Do not upload an existing activity merely as a test, to avoid a duplicate.
2. If Connect-to-app activity import matters, download one original activity FIT through Connect web, verify and decode it locally, then decide whether to add a dedicated import command.
3. If Connect course sync matters, import one user-chosen route through Connect web and send it with the phone app; compare the result with the already verified direct USB course import.
